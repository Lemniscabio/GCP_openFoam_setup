A) MPI = Physical Cores

Core util 100% | vCPU util 50%

Each MPI rank gets a full physical core. vCPU utilization is 50% because only one hyperthread per core is used. This is the better strategy for compute-dense CFD workloads.

For compute-dense CFD, dedicating full cores to MPI ranks is the better strategy.

Key Takeaways

  • Best config: c2d-standard-16 with MPI=cores (8 ranks) — 53 min, $0.64 total
  • c2d beats c3d at every size for this OpenFOAM workload, despite Google's claim of ~40% improvement on c3d
  • MPI = physical cores outperforms MPI = vCPUs. Hyperthreading adds overhead for compute-dense CFD solvers
  • Max decomposition is 8 subdomains for this mesh. 16 subdomains causes SIGFPE — awaiting professor input
  • Memory is over-provisioned: Only ~3 GB used. highcpu variants (half memory, lower price) are the right choice
  • Local SSD vs boot disk makes no measurable difference — solver is CPU-bound, not I/O-bound
